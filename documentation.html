Introduction to Mobil Duaaaaaar

Welcome to the official documentation for Mobil Duaaaaaar. This framework provides a robust, high-performance foundation for vehicular combat, physics-based destruction, and explosive visual effects within Unity.

💡

Note: This documentation is structured for developers. If you are an artist looking for asset integration guidelines, please refer to the Custom Vehicles section.

The system is built on a modular architecture, ensuring that you can decouple the driving mechanics from the damage simulation if needed. We utilize Unity's Data-Oriented Technology Stack (DOTS) in specific computationally heavy modules for maximum frame rates during large-scale explosions.

System Architecture

Understanding the core loop of Mobil Duaaaaaar is essential before modifying the codebase. The architecture is primarily divided into three interconnected layers:

  1. Input & Physics Layer: Handles raw wheel colliders, torque application, and suspension telemetry.
  2. Damage Simulation Layer: Listens to collision impulses and calculates mesh deformation and part detachment.
  3. VFX & Audio Layer: Triggers particle systems and spatial audio based on the intensity of the damage layer events.
⚠️

Warning: Modifying the FixedUpdate cycle of the Physics Layer directly without using our abstraction classes may result in unpredictable rigidbody jitter during high-speed collisions.

Quick Start

To get started quickly, you can initialize a basic destructible vehicle using our pre-built setup script.

Installation via Package Manager

Add the following to your manifest.json:

"dependencies": {
  "com.megomago.mobil-duar": "https://github.com/megomago/mobil-duar.git#v2.1.0"
}

Basic Initialization

Attach the DuarController to your root vehicle GameObject:

using Megomago.MobilDuar.Core;

public class GameStarter : MonoBehaviour 
{
    void Start() 
    {
        // Initialize the vehicle with default explosive parameters
        var myCar = VehicleBuilder.Create()
            .WithEnginePower(500f)
            .WithExplosiveYield(ExplosionYield.Massive)
            .Build();
            
        myCar.StartEngine();
    }
}

Damage System v2.0

The newly overhauled Damage System v2.0 introduces vertex-level mesh deformation and procedural part detachment. Instead of relying on pre-fractured meshes, the system dynamically recalculates normals and UVs upon impact.

Configuration Parameters

Parameter Type Description Default
DeformationThreshold float The minimum collision impulse required to trigger mesh bending. 150.0f
DetachmentProbability float Chance (0-1) of a loose part falling off upon secondary impact. 0.45f
CalculateInternalDamage bool If true, transfers kinetic energy to engine health. true
🚀

Performance Tip: If targeting mobile devices, disable CalculateInternalDamage and increase the DeformationThreshold to save CPU cycles.

CarController API

The CarController class is the main entry point for manipulating vehicle behavior at runtime. It interfaces directly with the Unity physics engine.

Methods

public void ApplyNitrous(float duration, float multiplier)

Injects a temporary boost of torque to the rear wheels.

  • duration: Time in seconds the boost lasts.
  • multiplier: Torque multiplier (clamped between 1.5x and 4.0x).
public void TriggerCatastrophicFailure()

Forces the vehicle into a destroyed state, bypassing all health checks. Triggers the primary explosion sequence and detaches all marked visual nodes.

Optimization Guide

When spawning multiple "Mobil Duaaaaaar" instances in a single scene, consider the following best practices:

  1. Object Pooling: Always pool your explosion particle systems and detached car parts. Instantiating complex prefabs during a collision frame will cause noticeable stutter.
  2. Mesh Colliders: Avoid using MeshColliders for the vehicle body. Use compound primitive colliders (Box, Sphere, Capsule) to approximate the shape.
  3. LODs (Level of Detail): Ensure your car models have at least 3 LOD levels. Damage deformation should only be calculated for LOD 0 and LOD 1.
